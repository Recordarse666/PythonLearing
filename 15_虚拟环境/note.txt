你的程序  import requests  →  依赖了 requests 这个库
                                    │
                        requests 需要先 pip 安装
                                    │
                    不同项目可能要 requests 的不同版本
                                    │
                共用一个全局环境 → 版本冲突（打架）
                                    │
                解决方案：虚拟环境（每个项目独立一间房）


模块/库	    别人写好的现成代码
依赖	        你 import 的那些库
requests	一个「发网络请求」的第三方库
版本冲突	    两个项目要同一库的不同版本，共用一个环境会打架
虚拟环境	    给每个项目独立的房间，各装各的，互不影响
#############################################################
一、建立虚拟环境（3 步）
# 第1步：进入你的项目目录
cd 你的项目目录

# 第2步：创建虚拟环境（名字通常叫 .venv）
python -m venv .venv

# 第3步：激活（Windows）
.venv\Scripts\activate
激活成功后，命令行提示符前面会出现 (.venv)，说明你已经进入虚拟环境了。
##############################################################
二、查看依赖（重点）
1. 查看已安装的所有依赖 + 版本
pip list
输出类似：
Package    Version
---------- -------
requests   2.31.0
numpy      1.26.0
pip        23.0
pip list 就是「列出当前环境装了什么库、什么版本」。

2. 查看某个具体库的版本
pip show requests
输出这个库的详细信息：版本、安装位置、依赖了谁等。

3. 导出依赖（保存成文件，用于迁移）
pip freeze > requirements.txt
这会生成一个 requirements.txt 文件，内容长这样：

requests==2.31.0
numpy==1.26.0
作用：把「当前环境装了啥、啥版本」记录到文件里，别人拿到这个文件就能复现一模一样的环境。

4. 从文件安装依赖（别人给你 requirements.txt 时）
cdpip install -r requirements.txt
